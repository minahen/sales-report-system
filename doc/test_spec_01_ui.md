## 1. テスト方針・テスト種別

### 1-1. テスト種別と対象ドキュメント

| 種別 | 対象ドキュメント | 本ファイルの対象 |
|------|-----------------|-----------------|
| UIテスト | 画面定義書 | ○ |
| バリデーションテスト | バリデーション・エラーメッセージ一覧 | ○ |
| APIテスト | API仕様書 | test_spec_02_api.md |
| 業務フローテスト | 画面定義書・API仕様書 | test_spec_03_e2e.md |
| 非機能テスト | 要件定義 | test_spec_04_nonfunc.md |

### 1-2. テストケース記述凡例

| 列名 | 説明 |
|------|------|
| テストID | `画面ID-連番`（例：LOGIN-001） |
| テスト観点 | テストで確認する内容の分類 |
| 前提条件 | テスト実施前に満たすべき状態 |
| 操作手順 | テスト実施の手順 |
| 期待結果 | 合格とみなす結果 |
| 優先度 | 高／中／低 |

### 1-3. 優先度基準

| 優先度 | 基準 |
|--------|------|
| 高 | 基本業務が成立しない場合に影響する機能。必ずリリース前に確認 |
| 中 | 業務上重要だが代替手段がある機能 |
| 低 | UI上の細かい挙動・表示確認 |
