## 1. テスト方針

E2Eテストは実際のユーザー操作に沿ったシナリオで、複数の画面・APIをまたいで機能が正しく連携していることを確認する。

### 1-1. テストケース記述凡例

| 列名 | 説明 |
|------|------|
| ステップ | 操作の順序番号 |
| 操作者 | 操作を行うユーザー（テストデータ定義を参照） |
| 操作内容 | 実施する操作の詳細 |
| 期待結果 | そのステップで確認すべき結果 |
| 確認方法 | UI / API / DB のどこで確認するか |

## 3. シナリオ詳細

### SCN-01 日報の作成〜提出〜上長確認の一連フロー

**概要:** 営業担当者（USER-01）が当日の日報を作成・提出し、上長（USER-03）が確認・コメントするまでの基本フローを確認する。

**前提条件:**
- USER-01・USER-03がシステムに登録済み
- CUST-01・CUST-02が顧客マスタに登録済み
- 当日のUSER-01の日報が未作成

| ステップ | 操作者 | 操作内容 | 期待結果 | 確認方法 |
|----------|--------|---------|---------|---------|
| 1 | USER-01 | `tanaka@example.com` / `Password01` でログイン | 日報一覧画面へ遷移し「今日の日報を作成」ボタンが表示される | UI |
| 2 | USER-01 | 「今日の日報を作成」をクリック | 日報作成画面が開き、本日の日付が表示される | UI |
| 3 | USER-01 | 訪問記録1行目：顧客＝CUST-01（株式会社アルファ）、内容＝「新製品の提案を実施」、時刻＝「10:00」を入力 | 入力が反映される | UI |
| 4 | USER-01 | 「訪問記録を追加」をクリックし2行目：顧客＝CUST-02（株式会社ベータ）、内容＝「課題ヒアリング実施」を入力 | 2行目が追加され入力が反映される | UI |
| 5 | USER-01 | Problem欄に「株式会社アルファ担当者が来月異動予定」を入力 | 入力が反映される | UI |
| 6 | USER-01 | Plan欄に「株式会社ベータの提案資料を作成する」を入力 | 入力が反映される | UI |
| 7 | USER-01 | 「提出する」をクリック | 「提出しました」トースト（緑）が表示され、日報一覧画面へ遷移する | UI |
| 8 | USER-01 | 日報一覧画面を確認 | 当日の日報がステータス「提出済」で表示される | UI |
| 9 | USER-01 | ログアウト | ログイン画面へ遷移する | UI |
| 10 | USER-03 | `yamada@example.com` / `Password03` でログイン | 日報一覧画面（グローバルナビに「部下の日報」あり）へ遷移する | UI |
| 11 | USER-03 | グローバルナビから「部下の日報」をクリック | 部下の日報一覧画面が表示される | UI |
| 12 | USER-03 | USER-01の当日日報（提出済）を確認 | 一覧にUSER-01の提出済日報が表示され「確認する」ボタンがある | UI |
| 13 | USER-03 | 「確認する」をクリック | 日報詳細画面が開き、ステップ3〜6で入力した内容が正しく表示される | UI |
| 14 | USER-03 | コメント欄に「アルファ社の件、引き続き対応をお願いします」を入力し「コメントを投稿する」をクリック | コメントがUSER-03の名前・投稿日時とともに表示される | UI |
| 15 | USER-03 | 「確認済にする」をクリック | ステータスが「確認済」に変わり「確認済にする」ボタンが非表示になる | UI |
| 16 | USER-01 | 再ログインして当日の日報を確認 | ステータスが「確認済」になっており、上長コメントが表示されている | UI |

### SCN-02 日報を下書き保存し後日に再編集して提出

**概要:** 作業途中で下書き保存し、後日の続きから再編集できることを確認する。

**前提条件:** USER-01がログイン済み、当日の日報が未作成

| ステップ | 操作者 | 操作内容 | 期待結果 | 確認方法 |
|----------|--------|---------|---------|---------|
| 1 | USER-01 | 日報作成画面を開き、訪問記録1件（顧客・内容入力済）とProblemのみ入力して「下書き保存」をクリック | 「保存しました」トーストが表示され、編集画面が継続表示される | UI |
| 2 | USER-01 | 日報一覧画面へ遷移 | ステータス「下書き」の日報が表示されており「編集」ボタンがある | UI |
| 3 | USER-01 | 「編集」ボタンをクリック | ステップ1で入力した訪問記録・Problemがフォームに復元される | UI |
| 4 | USER-01 | Plan欄を入力し「提出する」をクリック | 「提出しました」トーストが表示され、ステータスが「提出済」になる | UI |
| 5 | USER-01 | 提出済み日報の「表示」ボタンをクリック | 日報詳細画面が表示され、編集ボタン・編集フォームが存在しない | UI |
| 6 | USER-01 | 提出済み日報の編集URLへ直アクセス | 詳細画面へリダイレクトされる（または403） | UI / API |

### SCN-03 上長が複数部下の日報をまとめて確認・コメント

**概要:** 上長が複数の部下の日報を効率よく確認できることを確認する。

**前提条件:** USER-01・USER-02の両方の当日日報が提出済み状態で存在。USER-03でログイン済み。

| ステップ | 操作者 | 操作内容 | 期待結果 | 確認方法 |
|----------|--------|---------|---------|---------|
| 1 | USER-03 | 部下の日報一覧画面を表示 | USER-01・USER-02の両方の日報が表示される | UI |
| 2 | USER-03 | 担当者セレクトで「田中 太郎」を選択して検索 | USER-01の日報のみ表示される | UI |
| 3 | USER-03 | 担当者セレクトを「全員」に戻してステータスを「提出済」で検索 | 両ユーザーの提出済み日報が表示される | UI |
| 4 | USER-03 | USER-01の日報を確認・コメント投稿・確認済みにする | 操作が成功し、ステータスが「確認済」になる | UI |
| 5 | USER-03 | 一覧に戻りUSER-02の日報を確認 | USER-01の日報はステータス「確認済」に更新されており「表示」ボタンに変わっている | UI |
| 6 | USER-03 | USER-02の日報も確認済みにする | 正常に完了する | UI |

### SCN-04 顧客マスタの登録〜日報での利用〜削除制御

**概要:** 顧客マスタに登録した顧客が日報で使用でき、使用中の顧客が削除できないことを確認する。

**前提条件:** USER-04（管理者）とUSER-01（営業）が存在

| ステップ | 操作者 | 操作内容 | 期待結果 | 確認方法 |
|----------|--------|---------|---------|---------|
| 1 | USER-04 | 顧客マスタ登録画面で「株式会社エプシロン」「IT」を入力して保存 | 一覧画面に「株式会社エプシロン」が追加される | UI |
| 2 | USER-01 | 日報作成画面を開き、顧客セレクトボックスを確認 | 「株式会社エプシロン」が選択肢に表示されている | UI |
| 3 | USER-01 | 「株式会社エプシロン」を選択し訪問内容を入力して提出 | 日報が正常に提出される | UI |
| 4 | USER-04 | 「株式会社エプシロン」の削除を試みる（確認ダイアログで「削除する」をクリック） | 「この顧客は訪問記録に使用されているため削除できません」トーストが表示 | UI |
| 5 | USER-04 | 訪問記録に紐づいていない別の顧客を削除 | 正常に削除され、一覧から消える | UI |

### SCN-05 営業担当者の追加〜日報作成〜担当者削除制御

**概要:** 担当者を追加し、その担当者が日報を作成した後、削除制御が機能することを確認する。

**前提条件:** USER-04（管理者）が存在

| ステップ | 操作者 | 操作内容 | 期待結果 | 確認方法 |
|----------|--------|---------|---------|---------|
| 1 | USER-04 | 営業マスタ登録画面で新規担当者「山本 新太郎」`yamamoto@example.com` `Password99` ロール「営業」 上長「USER-03」で登録 | 一覧に「山本 新太郎」が追加される | UI |
| 2 | 山本 | `yamamoto@example.com` / `Password99` でログイン | 日報一覧画面へ遷移する | UI |
| 3 | 山本 | 日報を1件作成・提出 | 正常に提出される | UI |
| 4 | USER-04 | 「山本 新太郎」の削除を試みる | 「この担当者は日報またはコメントが存在するため削除できません」トーストが表示 | UI |
| 5 | USER-04 | 日報が存在しない別の担当者を削除 | 正常に削除され、一覧から消える | UI |

### SCN-06 ロールごとのアクセス制御確認

**概要:** 各ロールが許可されていない画面・操作にアクセスできないことを確認する。

| 1 | USER-01 | グローバルナビを確認 | 「部下の日報」「顧客マスタ」「営業マスタ」が表示されない | UI |
| 2 | USER-01 | `/customers` のURLへ直アクセス | アクセス拒否（403またはリダイレクト） | UI / API |
| 3 | USER-01 | `/salespeople` のURLへ直アクセス | アクセス拒否（403またはリダイレクト） | UI / API |
| 4 | USER-01 | `/daily-reports/team` のURLへ直アクセス | アクセス拒否（403またはリダイレクト） | UI / API |
| 5 | USER-01 | 他ユーザー（USER-02）の日報詳細URLへ直アクセス | アクセス拒否（403またはリダイレクト） | UI / API |

#### 6-2. 上長ロール（USER-03）の制限確認

| ステップ | 操作者 | 操作内容 | 期待結果 | 確認方法 |
